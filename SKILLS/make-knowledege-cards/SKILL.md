# Make Knowledge Cards

## Overview

将一篇文章（用户直接粘贴的文本，或本地 .md/.txt 文件）提炼为 5-8 张知识卡。每张卡片只讲一个知识点，包含标题、核心知识、简明解释、例子或自测问题。提炼以原文为唯一依据：不编造、不重复、不凑数。

## 适用范围

适用输入：

- 用户在对话中粘贴的文章文本
- 本地 Markdown（.md）或纯文本（.txt）文件

暂不支持（明确告知用户，并引导其提供受支持的输入）：

- 网页抓取 / URL 抓取
- PDF 文件解析
- Anki 牌组（.apkg 等）导出对接
- 图形界面操作

## 工作流程

### Step 1 获取输入

1. 用户粘贴文本时，以粘贴内容为原文。
2. 用户给出本地文件路径时，读取 .md 或 .txt 文件全文作为原文。文件不存在、为空或格式不受支持时，报告具体问题，请用户提供受支持的输入，不继续生成。
3. 原文不足一句完整表达时，不生成卡片，直接说明原因。

### Step 2 盘点候选知识点

1. 通读原文，明确主题与论证结构。
2. 提取候选知识点，按重要性优先取：
   - 核心概念与定义
   - 关键事实、数据、结论
   - 方法、步骤、原则
   - 非显而易见的因果关系或洞察
   - 原文中的典型例子（供卡片示例使用）
3. 跳过：寒暄、过渡句、营销语、与主题无关的铺垫。

### Step 3 去重与归并

1. 同一知识点在原文多处出现（包括换说法重复）时，合并为一张卡。
2. 同一知识点有多个例子时，只选最典型的一个，其余丢弃。
3. 两个不同的知识点不得塞进同一张卡；一个知识点也不得拆成多张卡。

### Step 4 确定卡片数量

1. 原文信息充足时，生成 5-8 张卡片，按重要性取前 5-8 个知识点。
2. 原文信息不足时（短文、信息密度低、通篇重复、以叙事为主），只给确有依据的知识点出卡，数量 0-4 张均可：完全没有可提炼知识点（如纯个人叙事）时输出 0 张并说明原因。此类情况在输出开头注明："原文信息不足以支撑 5 张卡片，共提炼出 N 个知识点"。
3. 严禁凑数：不拆分知识点、不重复表述、不添加原文没有的信息来撑数量。

### Step 5 生成卡片

按「卡片格式」逐张输出，并遵守「质量规则」。

### Step 6 自检

输出前逐条核对，任何一条不满足则修改后再输出：

- 每张卡片只有一个知识点
- 每张卡片四个要素齐全（标题 / 核心知识 / 简明解释 / 例子或自测问题）
- 卡片全部内容（含简明解释和例子）都能在原文找到依据，无编造、无原文之外的推断
- 无重复或高度相似的知识点
- 数量在 5-8 张之间，或已按规则说明信息不足
- 标题具体、可独立理解，不使用"知识点 1"这类占位标题

## 卡片格式

每张卡片使用以下 Markdown 格式：

```markdown
## 卡片 N｜标题

- **核心知识**：一到两句话直接给出该知识点的结论。
- **简明解释**：2-4 句展开说明，帮助理解。
- **例子/自测**：原文中的例子，或一道自测问题（附答案要点）。
```

格式细则：

- 卡片从"卡片 1"开始连续编号，按重要性降序排列（卡片 1 最重要）。
- 标题以 8-24 字为宜，具体、可独立理解；含英文术语时以准确简洁优先，不为凑字数牺牲准确。
- 核心知识用陈述句给出结论，不写"本文介绍了"这类引导语。
- 简明解释只做展开说明，不引入原文之外的信息。
- 例子优先取原文中的例子；没有合适例子时，出 1 道自测问题并附答案要点。自测问题应检查理解而非考查细节记忆。
- 输出语言与原文保持一致；用户另行指定语言时按用户要求。

## 质量规则（硬约束）

1. 忠于原文：所有内容必须能回溯到原文，原文没有的信息一律不写。宁可少写，不可编造。
2. 一卡一点：每张卡片只承载一个知识点。
3. 去重：相同或高度相似的知识点只保留一张卡。
4. 不凑数：卡片数量以信息量为准，信息不足就少出卡并说明原因。
5. 独立可读：卡片脱离原文顺序也能独立读懂。

## 输出规则

1. 输出为 Markdown 知识卡文档，结构为：一行简短说明（原文主题 + 卡片数量）→ 各卡片按重要性排列。
2. 输入为本地文件时，默认将知识卡保存到源文件同目录，命名为 `<源文件名>.知识卡.md`，并在回复中告知保存路径与卡片内容。
3. 输入为粘贴文本时，直接在回复中输出卡片；用户要求保存时再写入文件。
4. 所有自测问题必须附答案要点。
5. 提炼出 0 张卡片时，用一段说明替代卡片（注明原文性质与原因），不生成占位卡片。
