# make-knowledege-cards

把文章转换成知识卡的 WorkBuddy Skill。

## 1. 项目解决什么问题

读完一篇长文后，手动提炼知识点费时费力：要点容易漏、重复内容难合并、复习时缺少自测材料。`make-knowledege-cards` 用一套固定的提炼流程，把一篇文章自动压缩成 **5-8 张可直接用于学习复习的知识卡**，并保证三点：只写原文有的信息、一张卡只讲一个知识点、信息不足时不凑数。

## 2. 主要功能

- **两种输入**：对话中粘贴的文章文本，或本地 Markdown（.md）/ 纯文本（.txt）文件
- **知识卡输出**：每张卡片包含标题、核心知识、简明解释、例子或自测问题（自测问题附答案要点），按重要性降序编号
- **质量硬约束**：忠于原文（不编造）、一卡一点、去重（换说法重复只出一张卡）、不凑数（信息充足 5-8 张；信息不足 0-4 张并说明原因，完全没有知识点时出 0 张）
- **暂不支持**：网页抓取、PDF、Anki 导出、图形界面

## 3. 安装方法

将 `SKILLS/make-knowledege-cards/` 整个目录复制到 WorkBuddy 的 Skill 目录即可，二选一：

| 范围 | 目标路径 | 说明 |
|------|----------|------|
| 用户级 | `~/.workbuddy/skills/make-knowledege-cards/` | 跨所有项目可用 |
| 项目级 | `<项目>/.workbuddy/skills/make-knowledege-cards/` | 与项目成员共享 |

目录内容（无额外脚本，拷贝即用）：

```
make-knowledege-cards/
├── SKILL.md               # 工作流程、卡片格式与质量规则
└── agents/
    └── openai.yaml        # OpenAI 兼容的 agent 配置（供对应运行器加载）
```

安装后在新会话中触发即可。可用官方脚本校验格式：

```bash
python <skill-creator>/scripts/quick_validate.py <目标路径>/make-knowledege-cards
# 输出：Skill is valid!
```

## 4. 使用方法

在对话中用自然语言触发，两种输入任选：

- **粘贴文章**：`把下面这篇文章做成知识卡：<文章正文>`
- **本地文件**：`把 <文件路径> 转换成知识卡`（仅支持 .md / .txt）

输出行为：

- 本地文件输入 → 知识卡保存到源文件同目录，命名为 `<源文件名>.知识卡.md`，同时在回复中展示
- 粘贴文本输入 → 直接在回复中输出卡片；需要保存时说一声，再写入文件

## 5. 输入输出示例

**示例一：本地文件输入**（`tests/articles/01-https-长文.md`，产出 7 张卡，文件保存为 `01-https-长文.知识卡.md`）

输入摘录：

> HTTPS 的全称是 HTTP over TLS，也就是在 HTTP 和 TCP 之间加了一层 TLS 协议。TLS 的核心作用是加密：客户端和服务器协商出一个只有双方知道的会话密钥……现代 TLS 更常用的是 ECDHE 密钥交换……它支持前向保密。

输出摘录：

> 《HTTPS 到底安全在哪里》共提炼 7 张知识卡。
>
> **## 卡片 2｜会话密钥用对称加密保障速度**
>
> - **核心知识**：TLS 用对称加密的会话密钥加密实际数据，加解密速度快、适合大量数据，但前提是双方先安全地拿到同一个密钥。
> - **简明解释**：对称加密的短板正在于密钥分发：第一次通信的信道本身不安全，不能指望直接把密钥明着发过去。因此 TLS 把"数据加密"和"密钥分发"拆成两个问题分别解决。
> - **例子/自测**：自测问题：为什么不用非对称加密直接加密全部通信内容？答案要点：非对称加密加解密开销大、速度慢，不适合加密大量数据，只适合用来交换密钥。

**示例二：粘贴文本输入**（评论类文章摘录，产出 7 张卡，直接输出在对话中）

输入摘录：

> 河野mora用来支付学费、生活费和孩子开支的自媒体账号，被她自己的父母一趟一趟举报到封禁。父母后来撤销了投诉，但平台的处罚已经生效，账号没有恢复……

输出摘录：

> 本文评述河野mora自媒体账号被父母举报封禁事件，共提炼 7 张知识卡。
>
> **## 卡片 2｜"家丑不可外扬"实为表达权归属之争**
>
> - **核心知识**："家丑不可外扬"表面是关于隐私的古老训诫，实际是一次争夺：谁有权定义"家丑"、谁有权决定哪些经历可以被讲述——两代人之间隔着的是表达权归谁的问题，不是名誉问题。
> - **简明解释**：女儿把成长经历当作内容素材，靠讲述自己的故事谋生；父母把同一段故事视为家庭形象的泄漏点。同一段经历，一方是生计，一方是形象泄漏点。
> - **例子/自测**：自测问题：为什么说两代人之间隔着的不是名誉问题？答案要点：女儿靠讲述自身经历谋生，父母视之为家庭形象泄漏，争的是谁有权决定哪些经历可以被讲述。

**示例三：信息不足时不凑数**（`tests/articles/03-爬山日记-信息不足.txt`）

输出：

> 《周末爬山记》原文信息不足以支撑 5 张卡片：这是一篇个人游记，以叙事和感受为主，没有可复用的知识点。共提炼出 0 张知识卡。

---

`tests/` 目录含 4 类测试文章（科技长文、方法短文、信息不足日记、重复内容文）及对应知识卡产出，测试结论见 `tests/测试报告.md`。
